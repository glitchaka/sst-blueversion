# SST 0.1.9-blue.76 — paquetes nativos .sstpkg y estructura Win/Unix

## Formato de paquetes SST-PACKAGE/1

- Nuevo contenedor propio .sstpkg (TAR comprimido con GZIP, manifest.json + payload).
- Archivos con SHA-256 por archivo, rutas y tipos de entradas validados; los enlaces y ejecutables externos .exe/.com/.bat/.cmd se rechazan.
- Despliegue por plataforma: packages/win/{modules,runtimes,data}/ y packages/unix/{modules,runtimes,environments,data}/, conservando la jerarquía de subdirectorios.
- Un archivo puede incluir árboles win y unix simultáneamente; instp extrae únicamente el destino declarado después de verificar toda la carga útil.
- Instalación local `instp install archivo.sstpkg` para paquetes registrados, además de descargas del catálogo.
- PowerShell se empaqueta como SST-PowerShell-win-x64.sstpkg, con SDK y DLL del motor integrado; no se distribuye un nuevo ejecutable de consola.
- Herramientas de proveedores sin adaptador SST permanecen identificadas como EXTERNO y no se instalan como .exe mediante instp.
- Arch WSL2 se registra como entorno Unix. Sus paquetes de datos/archivos Unix siguen un árbol independiente; instalar un paquete SST no altera automáticamente la raíz WSL.
- Conserva `instp upgrade sst` para actualizar el propio núcleo y `sigsour` como gestor visual de paquetes.

## Compatibilidad y controles

- Se conserva el registro de paquetes y el mecanismo de staging / rollback.
- Migración del directorio heredado del módulo PowerShell al árbol win/modules.
- Rust y GitHub Actions verifican el formato, la copia de DLLs, la instalación de PowerShell y las regresiones de Windows.
- Los adaptadores para intérpretes externos existentes siguen pendientes de una implementación embebida; no se presentan como plugins operativos hasta entonces.
