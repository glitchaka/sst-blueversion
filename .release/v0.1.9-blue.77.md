# SST 0.1.9-blue.77 — paquetes nativos .pkgx y catálogo sin Arch/WSL

## Paquetes y extensiones

- La extensión oficial de SST-PACKAGE/1 es **.pkgx**: TAR comprimido con GZIP, manifest.json y payload por plataforma.
- `instp install archivo.pkgx` y la instalación desde catálogo verifican metadatos, rutas, SHA-256, archivos obligatorios y staging.
- PowerShell se publica como `SST-PowerShell-win-x64.pkgx`. El módulo funciona dentro del proceso SST mediante su SDK .NET, sin abrir PowerShell.exe ni crear otra consola.
- El empaquetador `pack-pkgx.py` no contiene dependencias fijadas a PowerShell; permite `--require-file` por paquete.

## Arch: referencia para adaptar funciones, no entorno instalable

- Eliminados el paquete `arch` del catálogo, el comando `arch` y el adaptador ejecutable de WSL.
- Eliminada cualquier instalación de Arch Linux mediante `instp` y cualquier invocación a `wsl.exe` desde el gestor de paquetes.
- Los listados de paquetes de Arch solo sirven como referencias para futuras implementaciones nativas de SST; cada adaptación deberá usar su propio .pkgx.
- El catálogo de instp/sigsour ya no expone los antiguos 21 ejecutables ajenos como paquetes disponibles.
- Al iniciar, registros antiguos de WSL y ejecutables externos dejan de activarse en SST; no se eliminan las distribuciones ni los archivos ajenos de Windows.
- Los índices cacheados que no cumplen el contrato nativo se omiten sin impedir iniciar SST.

## Pruebas

- Regresiones de catálogo, bloqueo de ejecutables externos, validación PKGX y ejecución de PowerShell SDK.
- Se conserva `instp upgrade sst` para actualizar el núcleo de SST por el canal Blue.
