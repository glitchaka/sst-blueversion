SST — Autologon seguro mediante API de Windows

1. Función

Autologon permite configurar que una cuenta inicie sesión automáticamente
en Windows. SST usa CredUI para solicitar la contraseña y almacena el secreto
en LSA mediante LsaStorePrivateData (DefaultPassword), como documenta Microsoft.

No descarga Sysinternals ni ejecuta Autologon.exe, CMD, PowerShell o PWSh.
SST no transmite contraseñas por argumentos, variables de entorno ni archivos
temporales, y elimina el valor inseguro DefaultPassword del registro de Winlogon.

2. Sintaxis

  sys autologon enable -u CUENTA -d DOMINIO -p
  sys autologon -u CUENTA -d DOMINIO -p
  autologon -u CUENTA -d DOMINIO -p
  sys autologon disable
  autologon disable

  -u / --user        Cuenta local o del dominio
  -d / --domain      Dominio, nombre del equipo o punto para la cuenta local
  -p / --password    Abre un diálogo protegido de credenciales; NO acepta valor
  -h / --help        Muestra ayuda

3. Flujo protegido

  a. SST valida los parámetros sin aceptar contraseñas textuales.
  b. Si no está elevado, Windows pide autorización UAC.
  c. El proceso SST autorizado abre el diálogo de credenciales CredUI.
  d. La contraseña queda en memoria temporal de la aplicación, no en argv.
  e. SST deshabilita temporalmente el inicio automático (AutoAdminLogon=0).
  f. Elimina el valor DefaultPassword en texto claro del registro.
  g. Almacena el secreto en LSA y configura DefaultUserName/DefaultDomainName.
  h. Activa AutoAdminLogon=1 únicamente cuando finalizaron los pasos anteriores.
  i. Borra de memoria el búfer UTF-16 que entregó a la API.

No se guarda la contraseña en el historial de SST; en el editor integrado
no se pueden escribir caracteres después de -p hasta pulsar Enter.

4. Deshabilitar

  sys autologon disable

SST desactiva AutoAdminLogon, elimina DefaultPassword del registro y borra
el secreto LSA de inicio automático. Requiere autorización administrativa.

5. Seguridad y restricciones

El inicio automático reduce la seguridad física: alguien con acceso al
equipo encendido puede usar la sesión sin autenticación. Utiliza una cuenta
de privilegios mínimos y verifica las políticas locales y GPO.

Los secretos LSA se cifran para almacenamiento, pero no son invulnerables:
un administrador del dispositivo o un atacante con privilegios altos puede
recuperarlos. Consulta las recomendaciones de Microsoft antes de habilitarlo.

En sistemas unidos a dominio pueden afectar el inicio la disponibilidad de
red y las directivas de inicio de sesión. Un cambio de contraseña puede
deshabilitar el inicio automático hasta reconfigurarlo.

6. Cambio respecto de versiones anteriores

La sintaxis antigua:
  sys autologon -u USUARIO -d DOMINIO -p CONTRASEÑA

está PROHIBIDA. SST la rechaza antes de ejecutar los comandos. Si ya se
introdujo una contraseña real en versiones antiguas, debes rotarla, pues
podría estar en el historial, copias o registros externos. SST depura entradas
históricas reconocidas, pero no puede eliminar registros que estén fuera de
sus archivos.

7. Comprobación

  - Ejecuta sys autologon enable -u CUENTA -d DOMINIO -p.
  - Autoriza UAC si Windows lo solicita.
  - Escribe la contraseña únicamente en CredUI, no en SST.
  - Comprueba que SST no devolvió errores.
  - Reinicia el equipo y verifica la sesión automática.
  - Si deseas detener el mecanismo, ejecuta sys autologon disable.
